# dclang: Gotchas and compatibility notes

These are behavior observations from the cumulative audit. Consult the canonical references and tests before relying on edge cases.

- **Cells are untagged raw bits.** Stack and variable cells are `uintptr_t`; the operator chooses signed integer, unsigned integer, float, address, or other interpretation. dclang does not track or validate the intended type.
- **Integer and float vocabularies are distinct.** Use integer `+ - * / %` and comparisons for integer cells; use `f+ f- f* f/ f%` and `f...` comparisons/math for packed floats. `f%` has C `fmod` semantics. Use `i>f` and `f>i` for numeric conversion. Reinterpreting bits is not conversion.
- **`*/` is signed and range-checked.** It computes `(a * b) / divisor` with a double-width intermediate, truncates division toward zero, and reports zero divisors or final results that do not fit `intptr_t`.
- **Division-with-remainder order deliberately differs from Forth.** Standard Forth `/MOD` and `*/MOD` leave `( remainder quotient )`; dclang `/%` and `*/%` leave `( quotient remainder )`, matching the established `math.dc` word `divmod` and putting the remainder on top for the library's digit-expansion and Euclidean-style pipelines. Use `swap` when quotient-on-top composition is preferable. Remainders follow C signed-division semantics and therefore have the dividend/product's sign.
- **Numeric spelling selects parsing.** A decimal point or decimal exponent (`e`/`E`) produces packed `DCLANG_FLT`; otherwise the token is an integer. Thus `1` and `1.0` have different cell representations.
- **`clock` leaves two integer cells.** Its stack effect is `( -- epoch-seconds nanoseconds )`; it is not a packed float. Use `monoclock` for local elapsed-time benchmarks. The public musical timing API hides the absolute timestamp pair.
- **Output interpretation is explicit.** `.`, `u.`, and `f.` print signed integer, unsigned integer, and packed-float interpretations respectively. `.s` shows fixed-width raw hexadecimal without assigning a type.
- **Numeric sorts are homogeneous contracts.** `sortnums` compares signed integer cells; `fsortnums` compares packed floats and places NaNs last. Mixed arrays are not converted or diagnosed.
- **`exec` is dispatch, not eval.** It executes a named word supplied as a string; both user-defined words and registered primitives have been exercised.
- **Truth values and bitwise operations.** Canonical true is `-1`, false `0`; `not` and `and` are bitwise, not normalized logical operators.
- **Compiled loops.** `times ... again` and `for ... next` belong inside definitions. A zero or negative `times` count has been observed to execute the body once.
- **Indexed stack mutation.** `sinc`, `sincn`, and `ssetn` consume their index before addressing the remaining stack. Index `0` means the top remaining item. Increment operations are integer-domain; cells themselves remain untagged.
- **Fused variable operand order.** `+@` and `+inc!` take `base offset`. `+incn!` takes `increment base offset`; `+setn!` takes `value base offset`. Do not rearrange them to resemble `!` or arithmetic notation.
- **`factorial` zero case.** `0 factorial` was observed to return `0`, not the mathematical value `1`.
- **`gcd` name collision.** Both `math.dc` and `fractions.dc` define `gcd`; import order can matter.
- **`strslice` storage.** It returns a pointer into a shared buffer, overwritten by subsequent calls. The observed slice end is exclusive.
- **`strreplace` and `str+` buffers.** These are not ordinary immutable-string concatenation functions; callers must supply appropriate writable storage.
- **`fopen` failure display.** An unbuffered I/O test displayed a large unsigned-looking number for a failing file descriptor; signed representation remains under investigation.
- **Safety audit observations.** Potential unchecked indexing or NULL-pointer assumptions are documented as source-review concerns, not proven vulnerabilities.
- **`shuffle_cells`.** The exploratory test fixture was not conclusive; behavior remains unverified.
- **DSP sample rate is import-time state.** `dsp.dc` reads `SR` while imported and defaults to 44100. The playback script now passes the same `SR` to its sink. A generated `dclang2c-dsp` patch fixes the sample rate at compile time.
- **Phasor identity follows call order.** Oscillator wrappers allocate persistent phase implicitly by incrementing `_phasor_count`. `t+` resets the count for the next sample. Reordering, conditionally skipping, or moving oscillator calls can change which state slot a later oscillator uses.
- **Private DSP kernels are layout-sensitive.** `_phasor`, `_fm`, `_sineloop`, `_tri`, `_sawtooth`, `_delay`, `_port`, and `_reverb` accept normalized steps and internal memory addresses. `_reverb_cells` reports the storage needed by the generated Phiverb state. Prefer the public `dsp.dc` wrappers unless implementing or compiling the library itself.
- **Reverb state is a generated Faust object.** `make_reverb_struct` reserves that object in dclang's cell arena; do not assume the former eight-delay-line layout or manually inspect its fields. The public `reverb ( left right struct cutoff feedback -- wet-left wet-right )` effect is unchanged. Each named struct is an independent instance, and `_reverb` performs no callback-time allocation. Phiverb's eight comb lines use independent triangle modulation with the v6.5.5 FDN rates and time-domain depths; regenerate `dclang_phiverb.h` with `contrib/generate_phiverb.py` after changing the Faust source.
- **Fast math is approximate.** `fast_sin` accepts radians; `fast_sine` accepts oscillator frequency. Their measured maximum sine error is about `3.55e-6`. `fast_tanh` saturates at ±1 for inputs outside ±4; its measured maximum error on `[-4,4]` is about `6.71e-4`. Use the exact words when numerical identity matters.
- **`dclang2c-dsp` executes setup.** Compilation imports the source and runs its top-level setup in the host interpreter. Compile trusted inputs only. It is a bounded DSP patch compiler, not a general dclang-to-C compiler. The selected entry must leave exactly two samples, use balanced branches, and avoid loops, dynamic execution, and audio I/O.
- **`dclang2c-dsp` target width is part of translation.** Set `DCLANG2C_CELL_BITS=32` for Bela and `64` for a 64-bit target. Opaque state such as Phiverb occupies a width-dependent number of cells, so generated C deliberately refuses to compile on a target whose pointer width differs from the requested layout. Its render API defaults to `float`; overriding `DCLANG2C_SAMPLE_TYPE` requires a matching caller declaration.
- **Bela's NEON math backend is approximate.** Defining `DCLANG_MATH_NEON` and linking `-lmathneon` selects Bela's faster approximate functions for supported scalar math. Standard 32-bit builds use the corresponding `float` libm entry points. Check a patch's numerical ranges before enabling NEON.
